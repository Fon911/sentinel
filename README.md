# Sentinel

Сервис аутентификации на Go: регистрация, JWT с ротацией refresh-токенов и обнаружением кражи, ограничение попыток входа, двухфакторная аутентификация (TOTP).

![CI](https://github.com/Fon911/sentinel/actions/workflows/ci.yml/badge.svg)

## Возможности

- Пароли хранятся в виде хешей argon2id
- Access-токен на 15 минут, refresh-токен на 7 дней
- Ротация refresh: каждый обмен выдаёт новую пару, старый токен гасится
- Reuse-detection: повторное использование погашенного refresh отзывает все сессии пользователя
- Rate-limit: 5 неудачных входов, после этого вход закрыт на 15 минут
- 2FA (TOTP): QR-код для Google Authenticator, двухшаговый вход
- Logout идемпотентен: повторный выход не возвращает ошибку

## Стек

Go, chi, PostgreSQL, pgx, sqlc, goose, Redis (go-redis), golang-jwt, argon2id, pquerna/otp, Docker, GitHub Actions

## Как устроена безопасность

### Пароли

Пароли хранятся как хеши argon2id. Если базу украдут, пароли придётся подбирать перебором, а argon2id специально медленный и требует много памяти: тысячи попыток в секунду вместо миллиардов у SHA-256. Соль у каждого пароля своя, поэтому одинаковые пароли дают разные хеши.

На «нет такого email» и «неверный пароль» логин отвечает одной ошибкой. Иначе по ответам можно было бы узнать, какие email зарегистрированы, и подбирать пароли только к ним.

### Ротация и reuse-detection

При каждом обмене refresh-токена старый гасится и выдаётся новая пара. В Redis лежат только номера токенов: `refresh:<jti>` хранит id юзера (есть полка — токен живой), `sessions:<userID>` хранит номера всех живых refresh-токенов юзера.

Если пришёл токен с валидной подписью, но его номера уже нет на полке, значит, его используют второй раз. Честный клиент после ротации старый токен не присылает, поэтому копия есть у кого-то ещё. Мы не знаем, кто из двоих вор: он мог успеть обменять токен первым. Поэтому сервер отзывает все сессии юзера, и войти заново можно только по паролю.

### Rate-limit

Неудачные входы считаются в Redis по ключу `login_attempts:<email>`. Ключ строится из email, потому что проверка идёт до запроса в базу: id пользователя на этот момент ещё неизвестен, а у несуществующего email его нет вообще. После 5 промахов вход закрыт на 15 минут, даже с верным паролем; успешный вход обнуляет счётчик.

Таймер ставится только на первом промахе. Если бы каждый промах продлевал окно, атакующий мог бы держать аккаунт заблокированным бесконечно. Счётчик увеличивается командой `INCR`: она атомарна, поэтому одновременные попытки не теряются, в отличие от схемы «прочитал, прибавил, записал».

### 2FA

При настройке сервер генерирует секрет, сохраняет его в Postgres и отдаёт QR-код. Приложение на телефоне хранит секрет и каждые 30 секунд вычисляет из него и текущего времени 6 цифр; сервер при проверке вычисляет их так же и сравнивает. Сам секрет после QR по сети не передаётся. 2FA включается только после первого верного кода (`/auth/2fa/verify`), иначе пользователь, не отсканировавший QR, остался бы без доступа.

При включённой 2FA верный пароль выдаёт не токены, а одноразовый номерок на 5 минут. Токены выдаются только за номерок и верный код. После успешного входа номерок удаляется, чтобы перехваченным номерком нельзя было войти повторно.

## Модель угроз

| Угроза | Защита | Что не закрыто |
|--------|--------|----------------|
| Украли базу | пароли в argon2id, перебор очень медленный | — |
| Подбирают пароль | rate-limit: 5 попыток, потом блок на 15 минут | перебор многих аккаунтов с одного IP |
| Выясняют, какие email зарегистрированы | одна ошибка на «нет юзера» и «неверный пароль» | — |
| Украли refresh-токен | ротация и reuse-detection: при повторе отзываются все сессии | — |
| Украли пароль | 2FA: без телефона не войти | нет recovery-кодов |
| Перехватили номерок 2FA | живёт 5 минут и удаляется после входа | — |

## Запуск локально

Нужны: Go 1.27+, Docker, [goose](https://github.com/pressly/goose).

```bash
# 1. Postgres и Redis
docker compose up -d

# 2. Миграции
goose -dir migrations postgres "postgres://postgres:secret@localhost:5401/postgres" up

# 3. Запуск (порт 8000)
go run .
```

Переменные окружения:

| Переменная     | По умолчанию                                         | Что это                                        |
| -------------- | ---------------------------------------------------- | ---------------------------------------------- |
| `DATABASE_URL` | `postgres://postgres:secret@localhost:5401/postgres` | Postgres                                       |
| `REDIS_ADDR`   | `localhost:6379`                                     | Redis                                          |
| `JWT_SECRET`   | `dev-only-secret`                                    | ключ подписи токенов, в проде обязательно свой |

## Известные упрощения

- Нет recovery-кодов для 2FA: потерял телефон — доступ восстанавливается только вручную
- Rate-limit считает попытки по email, а не по IP: перебор паролей по многим аккаунтам с одного адреса он не остановит
- Один ключ HS256 для всех токенов, без ротации ключей
